# 阅读质量审计

这是审计记录，用于检查指南是否传达了可操作的理解，以及还剩哪些风险。

## 读者模拟

| 检查问题 | 从指南得到的答案 |
| --- | --- |
| 主路径是什么 | 纯 Java 下载器从请求、源探测到分块校验与成品提交 |
| 难点是什么 | 源可用和字节正确是两回事，重试与续传必须保留校验状态 |
| 阶段如何衔接 | 请求和摘要 → 探测/续传 → 按块选源和校验 → 落盘并提交 |
| 失败和边界在哪里 | 摘要可选；无 Range 不能续传；目标替换不承诺原子事务 |
| 如何验证理解 | 主流程末尾给出已有测试或检查入口；本轮未执行业务测试 |
| 从哪里改 | 代码地图逐项给出范围内目录、重要代码和验证位置 |

## 可证伪性与后续问题

证伪检查：若坏块仍标记 VERIFIED、缺块仍能提交，或把不同源 ETag 当作强一致依据，指南就失效。应重新读校验与续传分支，并运行现有真实 HTTP 回归。

读者下一问：native 后端怎样独立打包并满足许可义务？从 `docs/ARIA2.md`、`aria2/THIRD-PARTY-NOTICES.md` 和 native 脚本另行追踪，不能从 core 测试推导真机结果。

## 剩余风险

aria2 独立 artifact、JNI/native 构建与 Android 真机接线仅列入口，不追踪其实现；Maven 发布、包签名和历史 bundle 导入不在主流程范围。 文档结构验证和静态站点构建不能替代运行时、平台接线或生产验证；SOURCE 链接需在克隆/代码托管视图使用。README 原有丰富说明保留，root AGENTS 统一规则，CLAUDE 仅作路由。
